# Contribution conventions

## Shared

- Functions and helpers use action or predicate names.
- Name values for the fact they establish, not the helper that created them.
- Optional values use the `maybe` prefix.
- Name arguments whose types conceal their roles; self-describing domain values remain positional.
- Use imports instead of fully qualified paths.
- Inspect readability after formatting.
- Name meaningful conditions and expected values instead of extracting shallow helpers.
- Tests assert complete observable outcomes.
- Test setup is deterministic and local to its scenario.
- Separate Arrange, Act and Assert with blank lines.
- Declare test data in semantic scenario order.
- Cases differing only in inputs use a table test.
- Extend or retarget owning scenarios instead of adding coverage-only tests.
- Suite names identify production boundaries.
- Case names start with `should`, after any runner-required prefix.
- Keep nontrivial shared setup only where it owns common knowledge; avoid fixture carriers/frameworks and duplicate contract tests through consumers.
- Each Markdown prose paragraph or list item occupies one source line.
- Omit empty or repetitive sections.
- Commit subjects are imperative, at most 72 characters, and contain no issue/ticket identifiers.
- Explain the reason in the commit body when the diff does not; omit issue references.
- Preserve commit signing and repository identity.
- Never commit secrets or embed/print credentials.
- Read setup and gate commands from their executable owners and local guidance.
- Never weaken a gate to make a change pass.
- Describe observable guarantees positively.

## Scala
- Business modules use caller-defined trait, companion `make`, private final class `Live<CompanionObjectName>` (e.g. `LiveUserRepository` for `UserRepository`), then companion-owned results. Pure domain values need no artificial module machinery.
- Use operation-owned result enums for distinct business outcomes. Preserve an existing result contract when it expresses the operation completely; mechanical success or absence alone does not require a new enum.
- Generic capability and mechanical library APIs are outside this result-enum rule.
- Companion failure enums are named `Failure`.
- Top-level types are shared domain/config values, not orphan operation results.
- Private members omit explicit return types except for Unit.
- Public APIs declare return types.
- Runtime code has no default arguments.
- Multiple dependent steps use comprehensions.
- Keep comprehension generators contiguous.
- Aim for one physical line per comprehension statement. If it needs more, use the principles' guardrail discussion to check abstraction level and cohesion.
- Mixed effect generators and pure bindings need a same-abstraction-level reason.
- Name constructed dependencies when their responsibility merits a name. A long constructor/factory call prompts the guardrail discussion; extracting incidental values solely to shorten it does not resolve the concern.
- Keep assignments and chains on one line when they fit.
- Multiline lambdas use braces or colon syntax.
- Follow configured line limits.
- Destructure only when every field is required.
- Tuple callbacks use named pattern matching, not positional selectors.
- Public helpers are factories or mechanical utilities, not business-policy shortcuts.
- Shared codecs require multiple consumers and one shared representation invariant.
- Shared codecs contain pure bidirectional mappings only.
- Use a DTO only when a direct codec cannot express the format cleanly; keep it inside its adapter.
- Check changed refinement declarations and construction sites, including autoRefine.
- Production domain/usecases retain their required refinements.
- Non-core code, including tests in mirrored packages, retains a proof only for a required guarantee.
- Retain non-core refinements when a consumer needs their guarantee; reuse already-checked values where possible.
- Domain-valued test inputs and substituted port responses retain their constraints.
- Standalone expected catalogs use underlying types; safely widen actual refined outputs for comparison.
- Reuse checked test values while preserving complete outcomes, identity and order.
- Reduce repeated proof sites without casts, assumptions or fixture frameworks.
- Suppressions need site-specific proof of safety, smallest scope and full rule identifier; rationale is review evidence, not an explanatory comment.
- Name suites `<Boundary>ComponentTest` or `<Adapter>SeamIntegrationTest` according to the boundary they prove.
- Architecture rules use one ArchitectureTest with one test.
- Suite-local `buildX` helpers accept scenario-varying responses.
- Builder arguments put observation Refs first.
- At most one suite-local Refs records calls; it does not supply stub responses.
- Captured call observations preserve named argument roles; test control flags through explicit scenarios.
- Suite order is reusable meaningful data, scenarios, Refs and builders.
- Assertions normally fit one line through named expected/actual values.
- Test names interpolate the actual domain variant under test.
- Test setups follow the inspected precedent.
- Integration suites own resources directly, not through callback setup frameworks.
- Logging/runtime composition and coverage exclusions follow existing configuration; do not contort behavioral tests to cover glue.

## SolidJS / TypeScript

- Extend current style, dialog and feedback precedents.
- Keep domain content primary and editing chrome quiet.
- Source styles own presentation values and responsive treatment.
- UI headings, controls and hints use sentence case.
- Preserve proper names, saved content and catalog labels.
- Action names describe their effects.
- Display authoritative saved names instead of reconstructing them from IDs.
- Toolbar icons follow the existing visual language and remain visibly grouped.
- Icons have hover text and equivalent accessible names.
- Keyboard shortcuts belong to their interaction and coexist with text entry and native controls.
- Keep navigation, editing and viewing modes distinct.
- Follow the selected profile's import convention; preserve framework-required compiler/reactivity bindings.
- Pure validation/derivation/formatting is directly tested plain logic; component tests cover rendering/wiring rather than duplicating branch tables.
- Derived state uses accessors/createMemo; conditional rendering uses Show.
- Use For for keyed identity and Index for positional or primitive rows.
- Disabled-control explanations use the same predicate as disabling and are linked with `aria-describedby`.
- UI invariants mirror backend contracts and fail closed.
- Test through accessible roles/names and real events, not classes, structure or test IDs.
- Unreachable guarded branches may use required coverage directives with evidence; reachable paths earn coverage through user behavior.
